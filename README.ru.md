# Локальная лаборатория Vercel Bug Bounty

Воспроизводимый стенд для **локального** анализа исходного кода из программы [Vercel на HackerOne](https://hackerone.com/vercel). Инструменты не обращаются к Vercel и не запускают проверки против чужих сайтов. Правила и активы могут измениться: перед каждым исследованием сверяйтесь с [текущей политикой](https://hackerone.com/vercel) и [перечнем активов](https://hackerone.com/vercel/policy_scopes), а для open source — также с `SECURITY.md` выбранного проекта.

## Запуск

Нужны Python 3.10+ и Git. Сторонние Python-пакеты не требуются.

```sh
bash scripts/setup.sh
python3 -m unittest discover -s tests -v
```

`setup.sh` создаёт `.venv/` и закрытую от публикации `.workbench/` (`sources/` для кода, `private/` для заметок и артефактов). Исходники подходящего проекта и **стабильный релиз** выбирайте по актуальной политике и `SECURITY.md`; например:

```sh
git clone https://github.com/vercel/ms.git .workbench/sources/ms
git -C .workbench/sources/ms tag --list
# Выберите актуальный стабильный тег и проверьте SECURITY.md перед тестами.
TAG='REPLACE_WITH_STABLE_TAG'
git -C .workbench/sources/ms checkout --detach "$TAG"
.venv/bin/python tools/workbench.py scan .workbench/sources/ms
```

`scan` ищет места для **ручной проверки** в локальных JS/TS/Rust/Go-файлах; выводит только путь, строку и категорию, не содержимое файлов. Совпадение не является уязвимостью или готовым отчётом. Воспроизводите гипотезы локально на подходящем релизе и проверяйте цепочку воздействия. В стенд намеренно не включён автоматический сканер живых доменов.

Для ручной работы с прокси можно создать scope **только для своих** развёртываний (подтверждение владения — ответственность исследователя):

```sh
.venv/bin/python tools/workbench.py scope \
  --owned my-project.vercel.app --confirm-owned
# Файл: .workbench/private/burp-owned-scope.json
```

Генератор принимает только точные имена под `vercel.app` / `vercel.live`; он не разрешает `*.vercel.app`, `*.vercel.live`, `vercel.com` или `v0.app` целиком. Он не подтверждает владение технически и не заменяет правила программы. Не запускайте активный сканер без проверки scope и ограничения **не более 5 запросов/с к доменам Vercel**.

## Материалы и границы

- [Краткие правила исследования и отчёта](docs/RULES.ru.md) — конспект снимка политики от 22 сентября 2026 года и ссылки на первоисточники.
- [Шаблон приватного отчёта](templates/report.ru.md) — копируйте в `.workbench/private/`, не заполняйте в GitHub.
- [Исходный scope из приложения](references/attached-scope.json) — сохранён **только как исторический образец**; его широкие `include` не подтверждают право тестировать все указанные домены. Не импортируйте его как рабочий профиль.

Исходный текст политики из приложенного `pasted-text.txt` остаётся локально в `.hoplite/attachments/` и не публикуется в этом **публичном** репозитории: политика требует конфиденциальности материалов программы. Публикуются лишь ссылки и практическая памятка; данные об обнаруженных уязвимостях, PoC, записи и ответы сервисов храните только приватно и передавайте через HackerOne согласно правилам программы. `.hoplite/`, `.workbench/`, `.venv/` и типичные файлы с секретами исключены из Git.
